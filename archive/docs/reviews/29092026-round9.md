## Findings

### 1. The simulated label run fails its own check: true events are labeled 0 (high)

`check_label_pilot.py` exits with `DEL at 33333 overlaps a call labeled 0, not 1`, so the new CI step will fail. The labeled table:

| Truth | Call | Label | Reason | Max indel |
|:--|:--|:--|:--|:--|
| DEL HOM 3 kb | `ABC -> AC` HOM | **0** | clipped | 10 |
| INV HOM 800 bp | `ABC -> AB'C` HOM | **0** | clipped | 61 |
| INS HOM 800 bp | `AB -> A_B` HOM | NA | no_sequence | – |
| inv.del HOM 3 kb | `ABCD -> AC'D` HOM | 1 | validated | 41 |

There are two causes, both in how `haplotype_sequences` builds the query from the `blocks` column.

**(a) Whole flanking blocks are used as sequence.**
- The first and last blocks are the locus flanks: 33 kb and 30 kb here, and up to megabases on a real genome.
- The query becomes a 60+ kb sequence, and minimap2 does not align it end to end (`clipped`).
- The plan (and the paper) use **150 bp** of flank next to the event.

**(b) The uncovered breakpoint intervals are dropped.**
- Blocks now stop at each interval's edges, so the 35-55 bp between blocks is missing from both the alt and the ref sequence.
- That adds artificial indels as wide as the intervals: 61 bp on the inversion, above the 48 bp limit.

**What fixes it (checked on the same run):**

| Variant | DEL | INV | inv.del |
|:--|:--|:--|:--|
| as is | 0 clipped | 0 clipped | 1 |
| outer blocks trimmed to 150 bp | **1** | 0 large_gap (61) | 1 |
| gaps split at interval midpoint | 0 clipped | 0 clipped | 1 |
| midpoint + 150 bp | 0 low_identity (30) | 1 | 1 |
| **breakpoint at the soft-clip position + 150 bp** | **1** (id 1.000, indel 0) | **1** (id 1.000, indel 0) | **1** (id 1.000, indel 0) |

- Midpoints aren't accurate enough. A 30 bp error on a ~300 bp query fails the 90% identity rule.
- The caller already knows the clip positions (`_stamp_clip_positions` puts them on the blocks for insertions).

**Fix:**
- Have the caller write a point estimate per breakpoint: the clip position when the interval has one, else the interval midpoint. For example, add a `blocks_point` column with blocks that meet at those points. Keep `blocks` as is for uncertainty and the dashboard.
- In `label.py`, build sequences from `blocks_point`, and cut the first and last blocks down to 150 bp next to the event.
- Add a test that the simulated pilot labels every called non-insertion event 1.

**Process note:** the new CI step could not have passed. Please run `pytest` and the simulated pilot inside the container (`./scripts/arcsv2.ps1 --entrypoint bash ...`) before marking items done.

### 2. The pilot check is too lenient (medium)

- `check_label_pilot.py` passes when **one** true event is labeled 1, and silently skips events that were not called.
- In this run the HET 3 kb duplication at 99,999 was **not called at all** (20x, 200 kb), and nothing reported it.

Suggested:
- report missed events;
- require every called non-insertion event to be 1;
- require at least 3 of the 4 non-insertion events to be called at 20x.

### 3. Pilot scale (low)

- 5 events on 200 kb is right for CI speed.
- Add a second, local-only target (e.g. `make pilot-large`, or a `--events 40 --length 2000000` config) that runs the full label workflow and feeds `labels/` into the dashboard's ML tab. That's the dress rehearsal for M2.
