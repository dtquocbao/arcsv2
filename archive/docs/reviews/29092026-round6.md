# ARC-SV2 code review, round 6 — 2026-09-29

Follow-up to `29092026-round5.md`. The label work is still pending; see `docs/LABELS_PLAN.md`.

## How it was checked

- pytest 43/43 and ruff pass.
- Single-event simulator (60 kb, 30x, DEL/INV/DUP/DEL+INV, HOM and HET).
- 60-event simulator (3 Mb, 30x, 448k pairs), with `threads=1` and `threads=4`.
- SAM-level insertion simulator (100 / 300 / 1,500 bp, HOM and HET) through `arcsv2 call`.

## Results

- **Single-event:** 8/8 correct, unchanged.
- **60 events:** **55 / 60 correct, 0 false calls**, 37 s. The misses are the same five as round 5.
- **Threads:** `threads=1` 11.6 s, `threads=4` 11.9 s, with identical output. It is no longer 5x slower, but there is no speed-up yet either.
- **Insertions:**

| Truth | Call | Position (truth 30,000) | inslen |
|:--|:--|:--|:--|
| 100 bp HOM | `A_B` **HET** | **30000** | 100 |
| 100 bp HET | HET | 30000 | 100 |
| 300 bp HOM | HOM | 30000 | 316 |
| 300 bp HET | HET | 30000 | 316 |
| 1,500 bp HOM | HOM | 30000 | **316** (no `>` flag) |
| 1,500 bp HET | HET | 30000 | `>3162` |

Positions are now exact, where round 5 was 50-175 bp off.

## Fixed since round 5

- **Training** (`train.py`, `predict.py`):
  - A scaler is fit inside each model, with its mean and scale stored.
  - Folds use `GroupKFold` on `sample` when present, otherwise `StratifiedKFold`.
  - PCA is fit per class, the same way for out-of-fold and final models.
  - One-class folds give `None` scores that are left out of the threshold.
  - A chromosome hold-out report is stored in the manifest.
  - An untrained class now gives `ml_model=untrained`, `ml_prob=NA`. The `logistic(score_vs_ref/50)` fallback is gone.
- **`--threads`:** each worker gets a locus-only graph view (`_locus_view`).
- **Insertions:**
  - The junction is placed at the clip position inside the uncovered interval.
  - `inslen` is written as `>N` when the tested size is a lower bound.
  - merge-filter reads the `>` form.
- **Band rule:** the lower-copy / HOM preference now applies only when the two genotypes are the same block sequence apart from copy number (`select_in_band`). Deletion and inversion genotypes keep the higher likelihood. This is documented in `PARITY.md`.

## Open findings

### 1. Label pipeline not started (high; next milestone)

None of `LABELS_PLAN.md` M0/M1 is in the tree:

- `samio.py` has no `pysam` path, so the caller can't read the 1000 Genomes / HPRC CRAMs.
- The call table has no `blocks` column. Since breakpoint intervals are left uncovered, `ml-label` can't rebuild block sequences from `bp` alone.
- `label.py` / `ml-label` still take a precomputed hits table; there is no `mappy` alignment to haplotype assemblies.
- There is no `ml-dataset` and no `tests/test_label.py`.

The ML filter can't be trained on real data until M0 and M1 land.

### 2. Insertion lower-bound flag misses the HOM case (medium)

- 1,500 bp HOM is reported as `inslen=316`, a point estimate.
- `insertion_length_is_bound` flags only the largest tested size, or a size above `q_high` (~478).
- In a HOM insertion longer than the fragment, no pair spans it. The size is then set only by hanging reads and is not identifiable either.
- Suggested rule: also flag the size as a lower bound when no read pair spans the insertion block, i.e. every supporting read is hanging or clipped.

### 3. `--threads` gives no speed-up (low)

- On the 3 Mb test, genotyping is about half the time. The rest (`build_graph`, breakpoint discovery) is serial.
- `_locus_view` scans every edge of the chromosome for each locus, in the parent process.
- Build one edge index by block, once, and parallelize graph building by chromosome window if the chr20 timing shows it matters.

### 4. Genotypes (open, documented)

- 3 of 10 short HOM duplications are still called HET. `PARITY.md` now documents this as untuned until compared with upstream on the same reads.
- 100 bp HOM insertion called HET.
- Both belong in the genotype-concordance metric that the label plan records (`gt_concordant`).

## Still open: carried over

- No chr20 timing in `bench/RESULTS.md`. The Rust kernels are not called.
- `filter` is always PASS.
- No parity run against the original's example output.
- Model comparison (RF / XGBoost / LightGBM vs logistic) waits for labels.

## Suggested order

1. **M0:** `pysam` BAM/CRAM input (region-restricted) and a `blocks` column; test that SAM and BAM give identical calls.
2. **M1:** `label.py` + `ml-label` with `mappy`, `ml-dataset`, `tests/test_label.py`, as specified in `LABELS_PLAN.md` section 4.
3. **M2 pilot:** HG002 + 5 HPRC samples on chr20-22, which also gives the first real chr20 timing.
4. Insertion lower-bound rule (finding 2).
5. Once labels exist: model comparison per class with grouped nested CV.
