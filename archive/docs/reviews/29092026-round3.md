# ARC-SV2 code review, round 3 — 2026-09-29

Follow-up to `29092026-round2.md`. Changed files: `engine/breakpoints.py`, `engine/caller.py`, `engine/graph.py`, `engine/likelihood.py`, `tests/test_core.py`.

## How it was checked

- pytest 33/33, ruff pass.
- Same end-to-end simulator as round 2: 60 kb, 30x, one 1 kb SV at 30,000-31,000, no breakpoints supplied.
- Scaling spot check: one homozygous DUP on 60 kb, 240 kb and 960 kb chromosomes.

## Results

| Event | HOM | HET |
|:--|:--|:--|
| DEL | `ABC -> AC` HOM | `ABC -> AC` HET |
| INV | `ABC -> AB'C` HOM | `ABC -> AB'C` HET |
| DUP | `ABC -> ABBC` HOM | `ABC -> ABBC` HET |
| DEL+INV | `ABCD -> AC'D` inv.del HOM | `ABCD -> AC'D` inv.del HET |

All 8 cases are correct; in round 2, 3 were wrong. Runtime grew roughly linearly: 0.1 s, 0.7 s, 2.7 s for 9k, 36k, 144k pairs.

## Fixed since round 2

- Every pair is now stored on its edge, including pairs inside one block and pairs whose implied insert is out of range. Only adjacency support is conditional, as in `orig:add_pair`. Read depth now rules out the third copy: `ABBBC/ABBBC` scores -146643.8 vs -146595.5 for `ABBC/ABBC`.
- Breakpoint intervals are left uncovered between blocks (`orig:create_blocks`). Confidence intervals are clamped to the chromosome.
- The duplication test now asserts `ABBC` with HOM and HET cases, plus tests for storing reads without support, uncovered intervals and clamping.

## New findings

### 1. HOM k copies and HET k+1 copies tie exactly (medium)

- With every placement summed, `ABBC/ABBC` and `ABBBC/ABC` have identical log-likelihoods (-146595.46 in the HOM case, -145830.68 in the HET case).
- The new sort key breaks the tie toward fewer copies and then toward HOM. That gives the right answer here, but it is a modelling choice made by a tie-breaker, and the model cannot tell these two genotypes apart.
- Because the runner-up is the tied genotype, `score_vs_next` is `0.00` for every homozygous duplication (seen at all three chromosome sizes). That is a constant ML feature for the whole class. Either make `score_vs_next` skip genotypes that are likelihood-equivalent, or add a copy-number-aware feature.
- The HOM vs HET margin for the duplication is small: 2.4 log units (`ABBC/ABBC` -146595.46 vs `ABBC/ABC` -146597.84).
- Document the tie and the tie-break rule in `METHOD.md` and `PARITY.md`.

### 2. Within-block reads for every block count in the likelihood (medium, check parity)

- Upstream includes a within-block edge only when that block is duplicated in some path (`orig:sv_inference.py:950-966`, `which_dup`). Its per-library read counts come from the edges it passes, so reads inside non-duplicated flank blocks are left out of n.
- Here every within-block edge in the locus is scored and counted in n. This fixed the copy-number problem, but scores will differ from upstream. In the sim, DEL HET `score_vs_ref` went from 33.4 to 85.0.
- Cost: a locus now scores every read inside its flank blocks for every path. Flank blocks can be megabases on a real genome, times up to 1,000 paths. Either match upstream (within-block reads only for blocks duplicated in a candidate path), or score a constant read once rather than per path.

### 3. Affected length and call span now reflect interval width (low)

- Uncovered intervals shrink the affected blocks. With pair-only confidence intervals, `len_affected` for a 1,000 bp event came out as 964, 904, 959, 912, 983, 961, 930 and 806 (DEL+INV HET is the worst, about 20% short).
- `maxbp` can sit about 60 bp past the true breakpoint (31061 for INV HET).
- This likely matches upstream, but these numbers feed the 50 bp size filter and the ML features. Report `bp_uncertainty` from the interval widths, which are now real, instead of 0.

## Still open: carried over

- **ML filter not implemented.** `train.py`, `predict.py` and `features.py` are unchanged. No model is fitted, the "probability" is `logistic(score_vs_ref/50)`, and PCA is never fitted.
- **merge-filter.** BED files are not filtered by chromosome, and one sample can be counted twice in a merged call.
- **Scale.**
  - `cluster_drps` is O(n^2).
  - The whole SAM is loaded into memory.
  - `Graph.neighbors` scans every edge.
  - The Rust kernels are not called.
  - The spot check above had one SV. Genome-wide runs have thousands of loci.
- **Output columns.** `bp_uncertainty` and `sv_bp_uncertainty` are always 0 and `filter` is always PASS.
- **VCF.** Breakend brackets are the same for every junction orientation.
- **CLI.** `--threads` and `--jobs` are ignored, and `--region` uses only the chromosome.
- **Novel insertions.** Insertion blocks (`_`) are not searched.

## Suggested order

1. Decide the within-block read policy (finding 2) for parity and cost, and document the copy-number tie (finding 1).
2. Real `bp_uncertainty` and a non-degenerate `score_vs_next`, since both are ML inputs.
3. Scale: windowed DRP clustering, streaming BAM, an adjacency index, the Rust kernels, and a timed chr20 run recorded in `bench/RESULTS.md`.
4. Real ML training: per-class models, out-of-fold thresholds, PCA stored with the model.
5. Fix merge-filter chromosome handling and VCF breakend orientation, then run the parity check against the original's example output.
