## Fixed since round 4

- **Locus merge:** loci that only share a cut-point block stay separate (`PARITY.md` item 9). Genome-wide calling works now.
- **Near-tie band:** genotypes within 0.5 nats of the best form one band. Inside it the lower copy number wins, then HOM. `score_vs_next` is measured against the best genotype outside the band.
- **Path-count retry:** `max_mes_extra` works as upstream; the default is 0, as in the original.
- **Input and CLI:**
  - SAM records are paired as the file is read.
  - `--region chr:start-end` is honored.
  - `--jobs` runs chromosomes in separate processes, and `--threads` genotypes loci in separate processes.
- **Hanging reads:** distant mates (`class_probs[3]`) and the mate's own query length are used.
- **Novel insertions:** sizes are tested on a log-spaced grid at clip / insertion-pair boundaries, and the winning block is appended.
- **Training:** `ml-train` fits a per-class logistic model from a labeled call table. It stores the training PCA and out-of-fold thresholds in the manifest, with no pickling. `ml-predict` uses the stored coefficients.

## New findings

### 1. Training step (high, before any real labels are used)

`train.py` (`fit_labeled_calls`, `_oof_probabilities`):

- **No feature scaling.**
  - `LogisticRegression` runs on raw features whose scales differ by orders of magnitude: `span` in bp, `score_vs_ref` in the hundreds, fractions in [0, 1].
  - The default L2 penalty then shrinks features unevenly, and lbfgs may not converge.
  - Fix: a `StandardScaler` inside the model, with its means and scales stored in the manifest.
- **Folds are not grouped.**
  - `KFold(shuffle=True)` puts calls from the same sample, and the same site across samples, on both sides of the split.
  - The out-of-fold threshold will then be optimistic.
  - Fix: use `GroupKFold` on sample id, and report a chromosome hold-out as a second check.
- **Threshold computed on a different model than the one saved.**
  - The out-of-fold models refit PCA per class and per fold.
  - The saved model uses a PCA fit on all classes pooled.
  - The threshold is therefore calibrated for a different feature transform. Fit PCA the same way in both places.
- **Silent zeros.** When a training fold has one class, the fold is skipped with `continue`. Its test rows keep score 0.0 and still enter `choose_threshold`. Mark them missing instead, or stratify the folds.
- **Silent fallback.** With no fitted classifier, prediction still returns `logistic(score_vs_ref/50)` as `ml_prob`. It should write `ml_model=untrained` and `ml_prob=NA`, or refuse, so an untrained bundle can't pass for a trained one.
- **Only one model family.** There is no comparison of logistic regression, RF, XGBoost and LightGBM, and no nested CV. That's fine as a first baseline; see `LABELS_PLAN.md` step 6.

### 2. `--threads` is 5x slower (medium)

`caller.py` ~line 865 submits `_evaluate_locus(graph, ...)` once per locus. The whole chromosome graph, with every stored read, is pickled for each task.

Fix: send each worker only the locus's own blocks and edges, or hand the graph to the workers once through a pool initializer (a fork-inherited global works on Linux).

### 3. Insertion position, size and genotype (medium)

- **Position:** the call sits 50-175 bp left of the true junction even though exact soft clips at 30,000 exist. Report the clip position when the interval contains one, or use the interval's clip-supported end.
- **Size:**
  - Sizes above about the insert-size range can't be recovered from pairs: 1,500 bp came out as 316 (HOM) and 3,162 (HET).
  - Mark such calls as a lower bound (e.g. `inslen=>316` or a flag) rather than a point estimate.
  - Features and merge-filter should not use `inslen` as exact.
- **Genotype:** 100 bp HOM was called HET.

### 4. Duplication genotypes (open, as round 4)

3 of 10 HOM duplications are still called HET, all 300-800 bp. The band prefers HOM inside 0.5 nats, so HET is winning by more than the band here. Compare with upstream on the same input before tuning.

### 5. Band rule scope (low)

The 0.5-nat band with "prefer HOM" applies to every SV type, not only the duplication copy tie. For weak deletions and inversions this biases genotypes toward HOM. Either restrict the copy-number rule to paths that differ only in copy number, or document it as a global prior.
