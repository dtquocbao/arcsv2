## Findings

### 1. The midpoint fallback labels true events 0 (high, before M2)

- **The failing deletion:** a 300 bp HET deletion at 536580-536880.
  - The left breakpoint snapped to its clip (536580, exact).
  - The right interval (536794-536885) had **one** left-clipped read at 536880 in the BAM, against seven right-clipped reads at 536580.
  - One read is below `min_softclip_support = 2`, so no clip breakpoint exists there, and `blocks_point` fell back to the midpoint, 536839: **41 bp off**.
  - On a 150 + 150 bp query that fails identity (0.53).
- This is normal sampling at 10x per haplotype. Real data will do the same, often.
- **Why it matters for the ML:** a label of 0 should mean "the event is not real", not "the breakpoint is 40 bp off". Imprecise but real calls labeled 0 train the filter to reject real events.

**Fix, in order of preference:**

1. **Refine inside known intervals with any clip.** Discovery needs 2 clipped reads to *create* a breakpoint. But once an interval exists, even one clipped read inside it is a better point estimate than the midpoint.
   - Stamp `clip_pos` from single-read clips too (keep the most-supported position).
   - Mark in the output whether each point came from a clip or a midpoint, e.g. a `bp_point_source` column with values `clip` / `mid`.
2. **Tolerant labeling for midpoint breakpoints only.** When a breakpoint's point is a midpoint, try a few positions inside its uncovered interval (both edges, midpoint, and a 10 bp grid) and keep the best alignment.
   - Record the shift used (`label_bp_shift`).
   - Label 1 means the event validates at some position inside the call's own confidence interval. That matches what the call claims.
   - Cap the search, e.g. at most 3 midpoint breakpoints per call, so it stays cheap.

### 2. Tiny blocks create wrong complex calls (medium, caller)

The other label-0 call is a **correct** label for a wrong call:
- **Truth:** `inv.del` HOM, 300 bp, at 1951200-1951500.
- **Called:** `ABCDEF -> AD'F` (`other`), with blocks of 45, 54, 85, 116, **2** and 61 bp between the breakpoints. The extra small blocks B and E were deleted in the called path.
- The same pattern turned a 300 bp HET inversion into `AC'D` in rounds 4-5.
- **Suggested fix:**
  - Merge breakpoint intervals that are closer than a minimum block size, e.g. `min_affected_length`, before `create_blocks`.
  - Or drop blocks shorter than that when no discordant or split evidence ends inside them.
  - Then compare the 60-event simulation before and after.

### 3. Pilot tooling (low)

- `check_label_pilot.py` stops at the first mismatch. For the large pilot, print all mismatches as a table (truth, call, label, reason, breakpoint shift) before exiting non-zero.
- `pilot_large.py` should run the check itself, so `make pilot-large` gives a pass/fail.
- The 3 kb HET duplication at 99,999 in the CI pilot was missed again (20x). Keep an eye on duplication recall once real data exists.
