## Correction to round 3

Round 3 said upstream leaves reads inside flank blocks out of the likelihood. That was wrong. Upstream passes every locus block as `which_dup` (`orig:sv_inference.py:262`, `get_edges_in_range(g, list(range(start, end + 1)), ...)`), and `duplicated_blocks` is never called. The current behavior matches upstream. Thanks to Cursor for the check.

## New findings

### 1. Loci that only touch are merged, so genome-wide calling returns nothing (blocker)

On the 3 Mb, 60-event chromosome the caller returned **0 calls**. The log shows two loci, `0-65` and `67-121`, both `skipped_npaths`.

- `decompose` is correct: it returns small loci such as `(0,2) (2,4) (4,6) ...`, and adjacent loci share their cut-point block.
- `call_evidence` then merges the expanded loci with `if merged and start <= merged[-1][1]` (`caller.py` ~line 551). Touching loci chain into one huge locus that exceeds 1,000 paths.
- Upstream merges them as **open** intervals (`pyinter.open(s[0], s[1])`, `orig:sv_inference.py:190-193`), so loci that only share an endpoint stay separate.
- **Fix:** `start < merged[-1][1]`. With only that change:

| Metric | Result |
|:--|:--|
| Calls | 59 |
| Correct (type + genotype + rearrangement) | **54 / 60** |
| False calls outside events | 0 |
| Runtime, 3 Mb, 448k pairs | 39 s (21 s genotyping, 16 s graph build) |

- The single-event tests never catch this, because they only ever have one locus. Add a multi-event test, e.g. 3 events 50 kb apart, that asserts 3 calls.
- Every earlier round had this bug too; the 60 kb tests hid it.

### 2. The duplication "tie" is not exact on realistic data (high)

- The tie-breaker and the `score_vs_next` skip compare log-likelihoods rounded to 6 decimals. With uncovered breakpoint intervals, the extra length of a third copy no longer equals the block length exactly. The HOM `ABBC/ABBC` vs HET `ABBBC/ABC` difference is then small but not zero.
- On the 60-event run, two HOM duplications still had `score_vs_next = 0.00` with `rearrangement_next = ABBBC/ABC`.
- If the near-tie tips the other way, the call becomes a 3-copy HET. Nothing in the current rule prevents that.
- **Suggested fix:**
  - Treat genotypes as equivalent within a tolerance (e.g. |Δ log L| < 0.5, or a relative tolerance).
  - Apply the lower-copy-number rule inside that band.
  - Compute `score_vs_next` against the best genotype outside the band.

### 3. Duplication genotype accuracy (medium)

In the 60-event run, 4 of 10 HOM duplications were called HET. Three were 300 bp and one 800 bp, with `score_vs_next` 0.21, 6.14, 7.44 and 6.12, and `ABBC/ABBC` as the runner-up. All HET duplications got the right genotype, and all 3,000 bp HOM duplications were correct.

- The het/hom signal for short duplications is weak. Compare against upstream on the same input before tuning.
- It's worth reporting duplication genotype concordance as a separate metric once the ML filter exists.

### 4. Other misses on the 60-event run (low)

- One 300 bp HET duplication produced no call.
- One 300 bp HET inversion was called `AC'D` (BND,BND) because an extra 15 bp block (245894-245909) split the event. That's a breakpoint-merging issue for very short events.

### 5. Path-count fallback missing (low, parity)

When a locus exceeds `max_paths`, upstream raises the required edge support by 2 and retries, up to `max_mes_extra` (`orig:sv_inference.py:234-254`). The caller skips the locus straight away. Once finding 1 is fixed this matters less, but it is a parity difference for dense regions.

## Still open: carried over

- **ML filter not implemented.** `train.py`, `predict.py` and `features.py` are unchanged. No model is fitted, and the "probability" is `logistic(score_vs_ref/50)`. `PARITY.md` now says so.
- **Scale.**
  - The whole SAM is loaded into memory.
  - The Rust kernels are not called.
  - No chr20 timing yet. Extrapolating 39 s per 3 Mb gives about 14 min for chr20 single-threaded at this SV density; real data has far more breakpoints in repeats.
- **`filter`** is always PASS. `--threads`, `--jobs` and the coordinate part of `--region` are ignored.
- **Novel insertions.** Insertion blocks (`_`) are not searched.

## Suggested order

1. Fix the locus merge (`<` instead of `<=`) and add a multi-event test.
2. Replace the exact-tie rule with a tolerance band, and recheck HOM duplication genotypes.
3. Add the `max_paths` support-escalation retry.
4. Streaming BAM input plus a timed chr20 run in `bench/RESULTS.md`, then the parity run against the original.
5. Real ML training: per-class models, out-of-fold thresholds, PCA stored with the model.
