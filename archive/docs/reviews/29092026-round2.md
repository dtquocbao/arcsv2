# ARC-SV2 code review, round 2 — 2026-09-29

Follow-up to `29092026.md`, after the Cursor fixes.

## How it was checked

- pytest 30/30, ruff, `cargo test` all pass.
- End-to-end simulator: 60 kb chromosome, 30x, one 1 kb SV at 30,000-31,000, haplotype-aware read pairs fed to `call_evidence` with no breakpoints supplied.
- SAM-level simulator: same events, reads soft-clipped at junctions, run through `arcsv2 call`.

## Results

| Event | HOM | HET |
|:--|:--|:--|
| DEL | `ABC -> AC` HOM (correct) | `ABC -> AC` HET (correct) |
| INV | `ABC -> AB'C` HOM (correct) | `ABC -> AB'C` HET (correct) |
| DUP | `ABC -> ABBBC` HOM (wrong copy number) | `ABC -> ABBBC` HOM (wrong copy number and genotype) |
| DEL+INV | `ABCD -> AC'D` inv.del HOM (correct) | no call |

The SAM path gives the same calls. Soft-clip breakpoints land exactly at 30000 and 31000.

## Fixed since round 1

- Duplication edges need an outward pair (reverse read upstream of the forward read), following `orig:add_pair`. Concordant pairs in the insert tails no longer create them.
- Inversion pair types match `orig:pecluster.py` (both-reverse = InvR at 5' ends, both-forward = InvL at 3' ends), and FF/RR pairs now get graph edges.
- Each read's probability is summed over every placement of its two blocks in the path (`orig:get_block_distances_between_nodes`), using raw offsets plus block distance.
- Scoring uses only reads in the locus, and all of them count in the normalizer.
- Soft clips and split reads from the SAM become breakpoints, and split reads add junction support. Mate-unmapped reads are kept as hanging reads. TLEN comes from column 9.
- The KDE is capped at 3x median, and deletion-spanning pairs are excluded from the insert model.
- `PARITY.md` item 2 is corrected.

## Still open: new findings

### 1. Duplication copy number (high)

`ABBBC` beats `ABBC`: log-likelihood -1470.5 vs -1488.4 for the HOM case.

- Summing over placements doubles the probability of the 28 dup-junction reads under three copies.
- The normalizer only charges the 93 reads that sit on graph edges, so a longer haplotype costs almost nothing.
- Upstream stores every pair on its edge, including pairs inside one block and pairs whose implied insert is out of range (`orig:sv_parse_reads.py:44-49`; only adjacency *support* is conditional). It uses the within-block reads for duplicated blocks (`orig:sv_inference.py:950-966`). Those depth reads are what hold the copy number down.
- `build_graph` drops both kinds of pair.
- `test_deletion_duplication_and_inversion_from_pairs` only asserts `"BB" in rearrangement`, so `ABBBC` passes. It should assert `ABBC`, with HOM and HET cases.

### 2. Het DEL+INV complex missed (medium)

- Discordant-pair-only breakpoints land about 58 bp from the truth at the right junction. Reads near the junction fall into the wrong block and their implied inserts fail the 95% window, so that junction's edge has fewer than 2 reads and no alternative path exists.
- `create_blocks` starts each block at the merged interval's left edge and makes blocks contiguous. Upstream leaves the breakpoint interval between blocks uncovered (`orig:sv_parse_reads.py:356`), so block boundaries and block distances differ.
- A breakpoint confidence interval can go negative (a Del breakpoint at -1471 appeared in one run). Clamp it to `[0, chrom_len)`.

## Still open: carried over from round 1

- **ML filter not implemented.** `train.py`, `predict.py` and `features.py` are unchanged. No model is fitted, XGBoost and sklearn are never imported, the "probability" is `logistic(score_vs_ref/50)`, and PCA is never fitted.
- **merge-filter.** BED files are read without a chromosome filter, so every call is checked against all chromosomes' intervals. One sample can be counted twice in a merged call.
- **Scale.**
  - `cluster_drps` is O(n^2) (1k DRPs 0.14 s, 4k 2.4 s) and runs 5 times per type.
  - The whole SAM is loaded into memory.
  - `Graph.neighbors` scans every edge.
  - The Rust kernels are not called.
- **Output columns.** `bp_uncertainty` and `sv_bp_uncertainty` are always 0 and `filter` is always PASS, so those ML features are constant.
- **VCF.** Breakend brackets are the same for every junction orientation.
- **CLI.** `--threads` and `--jobs` are ignored, and `--region` uses only the chromosome.
- **Novel insertions.** Insertion blocks (`_`) are not searched. `PARITY.md` now says so.

## Suggested order

1. Store within-block and out-of-range pairs as upstream does, and tighten the duplication test to `ABBC` (HOM and HET).
2. Clamp breakpoint confidence intervals, and revisit how blocks are built from breakpoint intervals.
3. Scale: windowed DRP clustering, streaming BAM reads, an adjacency index, and calling the Rust kernels.
4. Real ML training (per-class models, out-of-fold thresholds, PCA stored with the model), with non-constant uncertainty and filter columns.
5. Fix merge-filter chromosome handling and the VCF breakend orientation.
